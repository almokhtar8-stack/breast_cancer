# Pre-analysis plan: GSE245601 single-cell preprocessing and malignant-cell identification

**Date written:** 2026-08-11
**Status:** locked before any candidate-gene expression is inspected. This
document must be written, and its thresholds frozen, before Step 4 (QC) is
applied to any cell. Amendments after that point must be appended, dated,
below — never silently edited in place.

This document governs **preprocessing and malignant-cell identification
only**. It explicitly does NOT authorize pseudobulk aggregation,
differential expression, candidate-gene inspection, or candidate ranking —
those require a separate, later pre-analysis amendment.

---

## 0. Scientific correction to the prior audit (frozen here)

The prior dataset-audit turn (see conversation history) incorrectly
described GSE245601's treatment arms as "E2 versus E2+4-OHT," borrowing
that framing from this project's Hany et al. 2023 CRISPR screen (see root
`PREANALYSIS.md` §2: "Contrast: E2 + 4-OHT versus E2 alone... the
gene-by-treatment interaction term"). **That E2-vs-E2+4-OHT construct
belongs to the Hany 2023 screen and must not be carried over into
GSE245601.**

The corrected, primary-source-grounded description of GSE245601, used
throughout this document and all downstream GSE245601 work:

> Primary ER+/HER2− human breast tumors and normal breast tissue, collected
> fresh at surgical resection, dissociated to single-cell suspension, and
> treated **ex vivo** with **10 µmol/L (4-hydroxy)tamoxifen or control
> media for 12 hours**, then processed for droplet-based scRNA-seq.

Source: GEO series summary/overall design (GSE245601) and Kim, Whitman et
al., *Clin Cancer Res* 2023;29(23):4894-4907 (PMID 37747807), Methods:
"live primary cell suspensions were treated ex vivo with tamoxifen (10
µmol/L) or control media for 12 hours."

**Observed but not used as primary framing:** the SRA BioSample
`treatment` attribute for these samples literally reads `Control (E2)` /
`Tamoxifen (E2+TAM)` — i.e. the depositors' own internal sample labels
note that the base culture media is estradiol-supplemented. This is
recorded here for completeness because it is real, verifiable primary-source
metadata, but it is **not** adopted as the primary description of the
experimental contrast: (a) neither the GEO series summary/design nor the
published Methods frames "E2 vs E2+4-OHT" as the tested contrast for this
dataset (unlike the Hany screen, which explicitly holds E2 constant across
both arms as a designed interaction term); (b) estradiol supplementation in
ex vivo primary breast tissue culture is a standard viability/media
component, not necessarily a manipulated experimental variable here. All
downstream GSE245601 documentation, tables, and figures will use **"Control
media" vs "10 µM tamoxifen, 12h, ex vivo"** as the treatment label, not
"E2 vs E2+4-OHT."

## 2. Primary analysis cohort (frozen)

**Primary cohort = Tumor_01 through Tumor_10, both conditions each (20
samples).** All 10 tumor pairs are used prospectively; the original paper's
post-hoc 4-tumor subset (selected by the authors based on their own
tamoxifen-response signature — see their Supplementary Table S5) is
**not** used to define our primary cohort, per this project's explicit
instruction to avoid inheriting a result-dependent sample selection.

`Normal_01`, `Normal_02`, and `T47D` remain in the downloaded archive and
sample manifest (public data, kept for completeness/future secondary use)
but are **excluded from the primary malignant-tumor inference cohort** at
this stage.

## 3. Provenance-tier convention

Every processing parameter below is tagged:

- **[A]** — stated explicitly in the published paper's Methods text (PMC10690085).
- **[B]** — found in the authors' code at the pinned commit, not (or not exactly) stated in the paper prose.
- **[A+B]** — stated in the paper AND independently confirmed/matched by the code (highest confidence).
- **[C]** — could not be reconstructed exactly from either source; a specific, documented, frozen decision was made here instead, clearly marked as ours, not the authors'.

## 4. QC rules (frozen; must not be altered after this point)

**[A+B]** Cell-level QC is applied per analysis block, with the primary
tumor cohort (`Tumor_01`-`Tumor_10`) matching the paper's "ABlock3" (stated
in-paper: *"ABlock3 included 10 pairs of primary tumor samples"*):

- `nCount_RNA >= 5000`
- `nFeature_RNA >= 2000`
- `percent.mt <= 25` (mitochondrial read percentage; **[A]** paper states
  cells with "a high percent mitochondrial read count (>25%)" are excluded;
  this exact number also matches the code's `th_percent.mt` default of 25.
  The paper's explicit >25% quote is anchored to "ABlock1 and ABlock4" in
  the text we could retrieve; no alternate mito value is stated or coded
  for ABlock2/3, so 25% is applied uniformly across all blocks including
  our ABlock3 tumor cohort — this uniform-application assumption is
  flagged **[C]** even though the numeric value itself is [A+B].)

Mitochondrial gene pattern: standard `^MT-` prefix (human, Cell Ranger
GRCh38 reference gene symbols) — **[C]**, not located verbatim in the
excerpted code; standard convention adopted and frozen here.

These thresholds are applied identically to Control and Tamoxifen cells
within a sample — **treatment condition is never used as a QC criterion or
covariate in thresholding**, satisfying the treatment-blinding requirement.

QC mode: direct thresholding ("arguments" mode in the author code), not the
MAD-based automatic-outlier mode, consistent with the paper's plain-language
statement of fixed numeric cutoffs rather than a described outlier
statistic.

## 5. Doublet detection (frozen)

**[A]** DoubletFinder (paper: *"After removing doublets by DoubletFinder"*).
Although the author code supports DoubletDecon and an intersection-of-both
strategy, the paper names only DoubletFinder, so DoubletFinder alone is
frozen as our method. Exact `pN`/`pK`/expected-doublet-rate parameters were
not stated in the paper; the code's approach (`pN=0.25`, `pK` selected via
`find.pK()`, expected doublet rate assigned by cell count via the standard
10x multiplet-rate table) is adopted — **[B]**.

## 6. Normalization, PCA, clustering (frozen)

**[A+B]** `NormalizeData(method="LogNormalize", scale.factor=10000)` →
`FindVariableFeatures(nfeatures=2000)` → `ScaleData` → `RunPCA(npcs=50)` →
neighbor graph and Louvain clustering on the first **30 PCs** at
**resolution 0.8**. (Paper: *"a shared nearest-neighbor graph was
constructed using 30 PCs, and Louvain clustering was performed with a
resolution of 0.8"*; *"summarization of the 2,000 most variably expressed
genes into 50 principal components."*) SCTransform is available in the code
but not evidenced as used (paper explicitly describes "log normalized").

UMAP parameters (`n_neighbors=30`, `min_dist=0.3`, `metric="cosine"`) —
**[B]**, code default, not stated in paper prose.

Raw UMI counts are preserved unmodified in a separate assay/layer
throughout — required for future pseudobulk work, never overwritten by
normalized/scaled values.

## 7. Broad cell-type annotation (frozen, candidate-gene-blind)

**[A]** Epithelial identity: basal cytokeratins **KRT5/KRT6A/KRT7/KRT14/KRT17**
and luminal cytokeratins **KRT8/KRT18/KRT19**, plus **FOXA1** for luminal
cells (paper: *"Basal (KRT5/14) and luminal (KRT8/18) cytokeratins were
enriched in the expected compartments"*; code confirms the extended
KRT5/6A/7/14/17 vs KRT8/18/19 panels).

**[B]** SingleR against **BlueprintEncodeData** (celldex) is the code's
default automated broad-lineage classifier, supplemented by PanglaoDB-derived
marker signatures for finer sub-typing and mast-cell/proliferation
signatures.

**[C]** The exact marker panels for T/NK, B/plasma, myeloid, fibroblast,
and endothelial lineages were not recovered verbatim from the paper text we
could access, and are not fully enumerated as hardcoded vectors in the
excerpted code (which instead defers most non-epithelial typing to
SingleR/PanglaoDB). We freeze standard, field-canonical marker sets for
these lineages (independent of the authors' exact panel, clearly labeled as
such): T/NK = `CD3D, CD3E, CD2, NKG7, GNLY`; B/plasma = `MS4A1, CD79A,
CD19, JCHAIN, MZB1`; myeloid = `CD68, LYZ, ITGAM, FCGR3A, CSF1R`;
fibroblast/stromal = `COL1A1, COL1A2, PDGFRB, DCN`; endothelial = `PECAM1,
VWF, CLDN5`. No candidate gene from the 13-gene sensitising panel or PAICS
appears in any of these marker sets.

**No cluster or lineage call may be adjusted based on any candidate gene's
expression.**

## 8. Epithelial subset

Cells assigned to epithelial-marker-dominant clusters (§7) are carried
forward as the epithelial subset per sample. This step performs no
malignant/non-malignant distinction.

## 9. Malignant-cell classification (the core of this phase; frozen before running)

**[A+B]** InferCNV reference (diploid/normal background) population:
**immune cells and endothelial cells** (paper: *"a normal background
composed of immune cells and endothelial cells"*; code: reference clusters
are those whose dominant SingleR-assigned label matches an
immune-plus-endothelial pattern, `identify_reference_clusters.R`).

**[A+B]** InferCNV run configuration — the **"vignettes"** (non-HMM) preset,
matching the author README's own example invocation
(`--type_infercnv_argset vignettes`) and consistent with the paper's Methods
never mentioning an HMM/Bayesian CNV step:

```
infercnv::run(cutoff=0.1, min_cells_per_gene=3, cluster_by_groups=TRUE,
              scale_data=FALSE, HMM=FALSE, analysis_mode="samples",
              denoise=TRUE, no_prelim_plot=TRUE, resume_mode=FALSE)
```

(`cutoff=0.1` is the package's own documented default for 10x/UMI data,
matching the code's `infercnv_cutoff` default and the code's own comment
"10x-genomics default; 1 for Smart-seq".) Run per sample
(`analysis_mode="samples"`), i.e. inferCNV is fit independently for each of
the 20 tumor samples, not on a merged cross-sample object.

**[A+B] Malignant-cell decision rule**, reconstructed from
`run_infercnv.R` (lines ~1089-1233 at the pinned commit) and matching the
paper's qualitative description (*"stratified into epithelial tumor and
epithelial normal cells by plotting scatter plots of the CNV values and the
correlation values with the top 5% of cells with high CNV values"*):

1. Per epithelial cell, compute a **CNV score** = mean of squared,
   reference-centered/scaled per-gene CNV values across the inferCNV output
   (`mean(scaled_value^2)`).
2. Within each cluster, take the **top 5% of cells by CNV score** (minimum
   2 cells) as a "seed" malignant reference set.
3. Compute each cell's **correlation** (Kendall tau) to the mean CNV
   profile of that seed set.
4. Compute adaptive, cluster-specific thresholds:
   `th_cna_value = mean(CNV score) − 2·SD(CNV score)`, clamped to `[0.01, 0.05]`;
   `th_cna_corr = mean(correlation) − 1.5·SD(correlation)`, clamped to `[0.2, 0.4]`.
5. A cell is called **malignant** if `CNV score > th_cna_value AND
   correlation > th_cna_corr`; otherwise **non-malignant epithelial**.

This is the code's `"ng_2021_and_thresholding"` variant — the most fully
specified, deterministic malignancy-decision branch available in the
author code, and the one most consistent with the paper's "top 5%" +
scatter/correlation description. **[C], explicitly flagged:** the exact CLI
default selecting this specific variant (vs. the simpler `"ng_2021"`
variant, which uses a single global `mean−2SD`/`mean−1.5SD` rule without the
`[0.01,0.05]`/`[0.2,0.4]` clamping) was not recoverable as a single literal
default from the excerpted code, and the paper text does not give numeric
correlation/CNV-value cutoffs itself. **We are freezing
`"ng_2021_and_thresholding"` as our primary method** because it is the most
complete, per-cluster-adaptive, fully-parameterized variant actually present
in the author code and is not contradicted by anything in the paper. This
choice is made now, before any cell has been classified, and before any
candidate gene has been inspected.

Cells not assigned to an epithelial cluster are never candidates for
malignant classification. Ambiguous cells (failing one but not both
threshold conditions) are labeled `non-malignant epithelial`, not dropped —
they remain in the epithelial-but-not-malignant category, visible in the
frozen metadata.

**Samples lacking adequate immune/endothelial reference cells**: the author
code has **no documented fallback** for this case **[C]**. We freeze our own
rule: a sample with fewer than 20 combined reference (immune+endothelial)
cells after QC is flagged `insufficient_reference` and excluded from
InferCNV/malignancy calling for that sample only (its pair partner is
independently evaluated on its own merits, per the frozen QC/reference
rules — pairing for the eventual pseudobulk eligibility flag is decided
later, in Step 10, strictly by the ≥50-malignant-cell rule below).

**Treatment blinding**: InferCNV is run identically on Control and
Tamoxifen cells of a sample using the same per-sample reference population
and identical thresholds; treatment condition is not an input to any step
of this procedure.

## 10. Independent malignancy sensitivity method (frozen before candidate expression is viewed)

**Primary** = the InferCNV `ng_2021_and_thresholding` procedure above.
**Sensitivity** = **CopyKAT** (Gao et al. 2021, *Nat Biotechnol*), a
CNV-based malignancy classifier that is methodologically independent of
inferCNV's implementation (different segmentation/clustering algorithm, its
own internal reference-cell inference rather than requiring us to supply
immune/endothelial reference labels). Run with default parameters
(`ngene.chr=5`, `win.size=25`, `KS.cut` auto-estimated, `distance="euclidean"`),
applied per sample to the same QC-passed epithelial cell set. This choice
and its parameters are frozen here, before any malignancy label — primary
or sensitivity — has been cross-referenced against any candidate gene.

Concordance between primary and sensitivity labels will be reported per
sample and overall; discordant cells are reported, not adjudicated by any
rule that references candidate-gene expression.

## 11. Pseudobulk pair-eligibility rule (frozen; pseudobulk itself is NOT run in this phase)

A tumor pair (`Tumor_XX` Control + Tamoxifen) is **provisionally eligible**
for a future pseudobulk phase only if **both** arms contain **≥50 primary
(InferCNV) malignant cells** after QC. This rule is frozen now and will not
be adjusted after malignant-cell counts are known.

## 12. What this phase explicitly does not do

No pseudobulk aggregation, no edgeR/DESeq2/limma, no per-cell or
pseudobulk Wilcoxon candidate tests, no candidate-gene expression
inspection (FeaturePlot, violin, or otherwise), no candidate-gene
involvement in any QC/clustering/annotation/malignancy decision, no
modification of the frozen CRISPR/GSE118713/NEBULA evidence classes, no use
of the original paper's post-hoc 4-tumor subset, no inspection of
Supplementary Table S5.

## Amendments log

**2026-08-11, amendment 1 (broad cell-type annotation method).** Section 7
listed SingleR + BlueprintEncodeData (celldex) as the author code's
default automated broad-lineage classifier **[B]**. Before running Step 6,
we are freezing a different, simpler method instead: per-cluster canonical
marker **module-score scoring** (`Seurat::AddModuleScore`), assigning each
cluster to its highest-scoring lineage unless the top score fails to
clearly dominate the second-best (margin < 0.05), in which case the
cluster is labeled `uncertain` rather than forced. Reasons: (1) this
project's own instructions for this phase explicitly state a preference —
*"Prefer the authors' documented canonical lineage-marker strategy over
introducing an unrelated automated annotation method"* — and the
authors' own documented, paper-stated marker strategy is precisely the
epithelial cytokeratin panel already frozen in section 7 **[A]**; SingleR
+ BlueprintEncodeData is a code-only, not paper-stated, dependency; (2) it
avoids introducing a large new reference-download dependency
(ExperimentHub/ AnnotationHub + BlueprintEncodeData) whose exact cached
version could not be pinned to match the authors' original run in 2023;
(3) it keeps the annotation step fully transparent and auditable (every
cluster's lineage call is traceable to an explicit marker list and a
numeric score margin) rather than delegating to an external classifier's
internal model. This is a deviation from the code's default, not from the
paper's stated method, and is recorded here before Step 6 was run — no
candidate gene was inspected before or in the process of making this
decision.

**2026-08-11, amendment 2 (DoubletFinder invocation bug, discovered and
fixed before any QC/doublet results were reviewed).** While validating
Step 4's implementation, `doubletFinder(..., reuse.pANN = FALSE, ...)`
raised `cannot xtfrm data frames` on the first sample. Root cause:
`reuse.pANN` is documented to take `NULL` (meaning "compute pANN fresh") or
a column-name string (meaning "reuse an existing pANN column") — passing
the literal value `FALSE` is not a valid sentinel and caused
`seu@meta.data[, FALSE]` (an empty-data-frame column selection) to be
mis-parsed internally by DoubletFinder as a pANN-reuse column, producing a
data-frame instead of a numeric vector three calls later. This was a bug in
our own invocation, not a change to any threshold or scientific parameter,
and not in DoubletFinder itself; it was found and fixed (`reuse.pANN =
NULL`) before any sample's doublet classifications were generated or
reviewed. Recorded here for full transparency per this project's provenance
conventions.

**2026-08-11, amendment 3 (small-cluster fallback for per-cluster
malignancy thresholding, frozen before InferCNV was run).** Section 9's
"ng_2021_and_thresholding" procedure computes adaptive CNV-value/
correlation thresholds per (sample, epithelial Seurat cluster) group. A
group with very few cells gives an unstable mean/SD estimate. We freeze
here: any (sample, cluster) group with fewer than 10 epithelial cells is
pooled with all other small groups in that sample into a single
`whole_sample_pooled` group for threshold estimation only (the per-cell
CNV score and correlation-to-seed computation are unaffected; only which
cells contribute to/share a threshold changes). This rule is applied
identically regardless of treatment condition and was frozen before any
sample was processed through InferCNV.

**2026-08-11, amendment 4 (gene-order file construction, frozen before
InferCNV was run).** The paper/code do not specify which exact gene-order
(genomic coordinate) reference file was used for InferCNV. We construct one
deterministically from TxDb.Hsapiens.UCSC.hg38.knownGene + org.Hs.eg.db
(Bioconductor, GRCh38/hg38 coordinates matching the Cell Ranger reference's
genome build), restricted to genes present in the expression matrix,
canonical chromosomes only (chr1-22, X, Y), one locus per gene symbol
(first Entrez match kept on the rare occasions a symbol maps to >1 locus).
This is a standard, documented way of building an InferCNV gene-order file
when one is not separately distributed, and does not involve any candidate
gene, expression value, or treatment condition.

**2026-08-11, amendment 5 (Kendall correlation implementation, performance
only, discovered and fixed before any malignancy label was computed).**
The frozen procedure (section 9, step 5) computes each cell's Kendall tau
correlation to the malignant "seed" profile across ~8,000 genes. Base R's
`stats::cor(method="kendall")` uses an O(n^2) algorithm that is
computationally intractable at this vector length (~1 second per cell,
i.e. hours for the full 20-sample cohort). We substitute
`pcaPP::cor.fk()`, an O(n log n) exact Kendall tau implementation,
verified to reproduce `stats::cor(..., method="kendall")` to floating-point
precision (max observed difference 5.5e-17 on test vectors) before use.
This is a performance-only substitution -- the statistic computed is
identical, not a different or approximate correlation measure -- and was
made before any sample's malignancy labels were computed.

**2026-08-11, amendment 6 (CopyKAT KS.cut parameter correction, discovered
and fixed before any sensitivity-method malignancy label was reviewed).**
Section 10 stated CopyKAT would be run with "`KS.cut` auto-estimated,"
which was incorrect -- `copykat()`'s actual documented default is
`KS.cut = 0.1` (a fixed numeric value, not an auto-estimation mode).
Passing `KS.cut = NULL` (an attempt to request auto-estimation that does
not exist in this package) caused an internal failure
(`CNA.MCMC(..., cut.cor = NULL, ...)` -> "argument is of length zero") at
the segmentation step, on all 20 samples. Fixed by using the package's
actual documented default, `KS.cut = 0.1`, confirmed working on a test
sample (Tumor_04_Control: 195 aneuploid / 56 diploid cells returned).
This is a correction to a factual error in this document, not a change to
which method or which of its documented defaults are used -- default
parameters throughout remains the frozen intent of section 10.
