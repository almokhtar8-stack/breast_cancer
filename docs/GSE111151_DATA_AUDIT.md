## 2. Study design (from GEO series/GSM records + paper abstract/Methods)

**This is genuinely tamoxifen resistance**, not a generic/other
endocrine-resistance state -- confirmed by both the series title and the
paper's own title/abstract ("Association of tamoxifen resistance and
lipid reprogramming in breast cancer"; "we created tamoxifen-resistant
breast cancer cell lines... Gene expression patterns revealed by
RNA-sequencing in seven tamoxifen-resistant variants were compared with
their isogenic parental cells").

- 4 parental ER+ breast cancer cell lines (MCF-7, T-47D, ZR-75-1, BT-474),
  each with exactly **one** sequenced parental sample (no biological
  replicate of the parental state within this series).
- 7 tamoxifen-resistant derivative sublines, generated by continuous
  culture with 1 µM 4-OH-tamoxifen for 8-12 months, unevenly distributed
  across the 4 parental backgrounds: MCF-7 (1: Tam1), T-47D (2: Tam1,
  Tam2), ZR-75-1 (2: Tam1, Tam2), BT-474 (2: Tam1, Tam2).
- **11 samples total** (4 parental + 7 resistant), confirmed directly
  from GEO (GSM3024053-GSM3024063) and from the downloaded files
  themselves (11 files in `GSE111151_RAW.tar`).
- Tam1 and Tam2 (where both exist for a line) are independently derived
  resistant sublines from the same parental culture, not technical
  replicates of each other or of the parental sample.
- Molecular subtype caveat: the paper states the panel represents
  "luminal A or luminal B" disease; BT-474 is conventionally classified
  as HER2-amplified/luminal-B-HER2+ in most literature, so the panel is
  not a molecularly homogeneous ER+/HER2- set -- a real biological
  confounder to note, not something to exclude or adjust away
  post-hoc.
- **Design implication:** with exactly one parental sample per cell line
  and an uneven number of resistant sublines per line, this is **not** a
  simple two-group unpaired (or 1:1 paired) comparison. It is a
  cell-line-blocked design: each cell line is its own block/stratum, and
  within each block, 1-2 resistant sublines are compared against that
  block's single parental sample. See `docs/GSE111151_PREANALYSIS.md`
  section C for the modeling decision this implies.
- This series is also described as including a "reanalysis of GSE58708"
  (a separate, external patient-tumor cohort) for a downstream
  cross-study comparison in the original paper. The series-level
  supplementary-file listing on GEO includes 8 file references bearing
  GSE58708's own original GSM IDs (GSM1417177-84) -- **these are not part
  of the 11-sample GSE111151 cell-line panel** and were confirmed absent
  from `GSE111151_RAW.tar` (which contains exactly the 11
  GSM3024053-63 files). They are noted here for provenance clarity only
  and are **not used** in this analysis, which is scoped to the 11-sample
  cell-line panel as the independent validation dataset, per the task
  instructions.

## 4. File format (verified directly, not assumed)

Each of the 11 per-sample files is a 5-column tab-delimited text file:
`EnsEMBL_GenID`, `gene_name`, `counts` (raw integer count), `CPM (log2)`
(non-batch-adjusted), `CPM_batch (log2)` (batch-adjusted). Confirmed by
direct inspection: **60,620 lines per file including a 1-line header
(60,619 genes)**, identical across all 11 files -- the earlier
observation of "roughly 60,619 rows" is confirmed exactly, not assumed.
`EnsEMBL_GenID` order is byte-identical across all 11 files (verified via
`md5sum` of the ID column), as is the `gene_name` column order, so the
files can be merged by row position without an explicit join. Zero
duplicate `EnsEMBL_GenID` values (unique primary key); 308 duplicate
`gene_name` values among 60,619 genes (Ensembl ID must be used for
unambiguous candidate lookup, not gene symbol alone). Zero NA/blank
values found in the `counts` column across all 11 files.

**"Batch" clarification (verified in the PMC full text, not assumed):**
the paper's "batch effect" correction (`limma`) is explicitly described
as correcting for "study origin" when merging this cell-line RNA-seq data
with the external GSE58708 **patient**-tumor cohort for a separate,
downstream cross-study comparison in the original paper -- it is not a
within-panel technical-batch correction for the 11 GSE111151 samples
themselves. The `CPM_batch (log2)` column is therefore **not used** in
this analysis; raw counts (`counts` column) are used to build an
independently-specified model for the within-GSE111151 comparison (see
`docs/GSE111151_PREANALYSIS.md`).
